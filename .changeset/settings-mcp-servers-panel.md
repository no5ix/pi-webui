Add **Settings → MCP Servers**, which reads and changes Pi's own MCP configuration on the selected machine — `<agentDir>/mcp.json` for the machine, and `<project>/.pi/mcp.json` for a trusted project, with a project entry that sets only `enabled` overriding a global server of the same name. Each server shows what the config says (enabled, disabled, or invalid, with the file, the command or URL, and the exposure) and what a connection test answered, because those are two facts: **Test Connection** completes Pi's handshake with a server and stops it, answering Reachable, Unreachable, or Needs sign-in, and it never opens a connection a session uses. Turning a server on writes the file and says to type `/reload` so Pi connects it. Environment and header values, OAuth secrets, a credential inside a server URL and a server's arguments stay in the file — an argument carries a token as often as an environment variable does — so the panel shows the command and the names, and a probe's message, including the server's own name, has the configured values cut out of it. A project's servers are read, changed, and connected only once the project is trusted, and a file that is not valid JSON is named with its position and left untouched. The project a page answers for is **named, never assumed**: the panel offers the selected machine's projects and opens on *No project*, where only the machine's global file is read and written. Each control says which entry it writes: a row's switch writes the definition with no project named and that project's override with a project named, naming the file on the row; *Remove project override* leaves the global definition in place and *Remove definition* leaves the override untouched, and a project that has both sees both controls — and a switch, probe, or armed removal belongs to the project and machine it was asked for: changing either drops the rows, the pending state, and the confirmation of the scope left.

Rebuild the workspace UI in React. The three columns — the session rail, the conversation, the workbench — are React components now, styled from PI WEB's own design tokens, and the screen a person sees is the same screen as before: running sessions and projects with their sessions in the rail, the streaming transcript with tool groups, thinking, images, skill rows, delivery marks and the queued-prompt footer, the composer with model, thinking and context chips, slash commands, shell `!` commands, file suggestions and attachments, the Git / Files / Terminal / Goals tabs, themes (including plugin themes and **Follow system**), the command palette, the session quick switcher, settings, dialogs, toasts and keyboard chords (`⌘K`, `⌘⇧P`, `⌘1`–`⌘4`, `⌘[`/`⌘]`, `⌘.`). Nothing was rebuilt underneath: the same API clients, the same session socket, the same board, transcript, panel-resize and theme engines are the source of truth, and plugin UI — Custom Elements — is hosted by the React shell: an installed plugin's composer contribution, its theme, and its `showDialog` surface appear as they did, loaded per machine from the manifest. A plugin that contributes its own workbench panel, settings section, nav section, transcript renderer, tool renderer or code-fence renderer is hosted by the previous shell, reachable with `?ui=legacy`. The previous shell is kept as the parity reference: add `?ui=legacy` to the URL (or set `pi-web-frontend` in local storage) to open it, which is how a reviewer compares one screen against the other.

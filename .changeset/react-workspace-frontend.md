Rebuild the workspace UI in React. The three columns — the session rail, the conversation, the workbench — are React components now, styled from PI WEB's own design tokens, and the screen a person sees is the same screen as before: running sessions and projects with their sessions in the rail, the streaming transcript with tool groups, thinking, images, skill rows, delivery marks and the queued-prompt footer, the composer with model, thinking and context chips, slash commands, shell `!` commands, file suggestions and attachments, the Git / Files / Terminal / Goals tabs, themes (including plugin themes and **Follow system**), the command palette, the session quick switcher, settings, dialogs, toasts and keyboard chords (`⌘K`, `⌘⇧P`, `⌘1`–`⌘4`, `⌘[`/`⌘]`, `⌘.`). The palette answers with the session and project operations a person reaches for — new, rename, pin, archive, archive with children, continue, detach, reload, stop, copy path, add project, close project, remove workspace, sign in, manage providers — and a command that has nothing to act on says why in its own words; the filter matches the words people type, so `kill` finds Stop and `archive tree` finds the descendant archive. Nothing was rebuilt underneath: the same API clients, the same session socket, the same board, transcript, panel-resize and theme engines are the source of truth, and plugin UI — Custom Elements — is hosted by the React shell: an installed plugin's composer contribution, theme, `showDialog` surface, **actions** (each contributed action is also a palette command, with its own group, chord and reason when it cannot run), **settings section**, **custom-message renderer** and **tool renderer** appear as they did, loaded per machine from the manifest, and a plugin's `prompt` control sends through the hosted prompt editor, which now exposes `submitPrompt()`. A plugin that contributes its own **workbench panel, global page, nav section or code-fence renderer** is hosted by the previous shell, reachable with `?ui=legacy`; asking the React shell for one of those says so in words rather than opening a tab with nothing behind it. The previous shell is kept as the parity reference: add `?ui=legacy` to the URL (or set `pi-web-frontend` in local storage) to open it, which is how a reviewer compares one screen against the other.

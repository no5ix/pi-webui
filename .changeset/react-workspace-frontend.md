Rebuild the workspace UI in React. The three columns — the session rail, the conversation, the workbench — are React components now, styled from PI WEB's own design tokens, and the screen a person sees is the same screen as before: running sessions and projects with their sessions in the rail, the streaming transcript with tool groups, thinking, images, skill rows, delivery marks and the queued-prompt footer, the composer with model, thinking and context chips, slash commands, shell `!` commands, file suggestions and attachments, the Git / Files / Terminal / Goals tabs, themes (including plugin themes and **Follow system**), the command palette, the session quick switcher, settings, dialogs, toasts and keyboard chords (`⌘K`, `⌘⇧P`, `⌘1`–`⌘4`, `⌘[`/`⌘]`, `⌘.`). The palette answers with the session and project operations a person reaches for — new, rename, pin, archive, archive with children, continue, detach, reload, stop, copy path, add project, close project, remove workspace, sign in, manage providers — and a command that has nothing to act on says why in its own words; the filter matches the words people type, so `kill` finds Stop and `archive tree` finds the descendant archive. Nothing was rebuilt underneath: the same API clients, the same session socket, the same board, transcript, panel-resize and theme engines are the source of truth, and plugin UI — Custom Elements — is hosted by the React shell: an installed plugin's composer contribution, theme, `showDialog` surface, **actions** (each contributed action is also a palette command, with its own group, chord and reason when it cannot run), **settings section**, **custom-message renderer** and **tool renderer** appear as they did, loaded per machine from the manifest, and a plugin's `prompt` control sends through the hosted prompt editor, which now exposes `submitPrompt()`. A plugin that contributes its own **workbench panel, global page, nav section or code-fence renderer** is hosted by the previous shell, reachable with `?ui=legacy`; asking the React shell for one of those says so in words rather than opening a tab with nothing behind it. The previous shell is kept as the parity reference: add `?ui=legacy` to the URL (or set `pi-web-frontend` in local storage) to open it, which is how a reviewer compares one screen against the other. The workbench got deeper: the Git tab now reads the commit history a page at a time and one commit's patch (a merge commit says so) and offers the one repository write the Git plugin backend performs, a new linked worktree, as a real form; the Files tab edits in the CodeMirror the composer already uses, with the grammar the machine names for the file, states the file's size, modification time and language, renders a markdown file as text, discards changes, and refuses to save a read the machine sent only in part rather than writing the fragment back over the file; the Terminal tab speaks the daemon's framed socket protocol, gains a coarse-pointer key row (Escape, `^C`, `^D`, Tab, arrows, Page Up/Down, Return), a full-height mode and a reconnect control. A session opened from a link is named by its first prompt instead of being called "no session open", and the composer stays at the bottom of the viewport instead of floating under a short transcript. Selecting a subject was made one decision instead of several guesses: opening a project chooses its main workspace and that workspace opens the session the browser was last reading there (a fresh page opens the first open project the same way and writes the address), a link that names only a session asks the machine where it lives and places it at the right project and workspace so the rail, the header, the transcript, the composer and the four workbench tabs all speak about the same thing, and the shell states what it is doing while it is doing it — "Looking for this session…", a session the machine reports gone titled as gone, a failed lookup named with the machine's reason, and a workbench that says the machine is finding the workspace of this session instead of claiming no workspace is chosen. A transcript whose socket is open is shown as live, so a loaded, updating conversation is no longer annotated as a stream that is still starting. A stream that closed before it opened — a stored session with no running runtime — is now named as closed, with the transcript on screen identified as the machine's stored history, and a file tree that did not answer offers Try again rather than leaving the reader with a sentence and no control.
